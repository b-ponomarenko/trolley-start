# CLAUDE.md

Guidance for Claude Code when working in this repository. See `README.md` for the full picture.

## Commands

```bash
npm run dev            # http://127.0.0.1:3000 (regenerates src/routeTree.gen.ts)
npm run build          # dist/client + dist/server
npm run preview        # serve the build
npm run typecheck
npm run test           # vitest
npm run test:e2e       # playwright: builds against e2e/mock-api.mjs, serves on :4173
npm run verify         # everything, in order
npm run format
```

Subsets: `npx vitest run src/modules/query`, `npx playwright test e2e/streaming.spec.ts`.

## What this is

- **Framework:** `src/core` (createApp/App, tokens, DI React bridge) and `src/modules` (command,
  logger, environment, http, query, render, router, ui-store). It must not import app code.
- `src/widgets` holds the app header and layout, plugged in through `LAYOUT_OPTIONS_TOKEN` in `src/index.ts`.
- **App:** `src/index.ts` (createApp), `src/router.tsx` (Start's `getRouter`), `src/routes`,
  `src/entities`, `src/shared`.

## Things that will bite you

- **Scopes matter.** Anything holding per-user state (query client, router, UI store, request
  commands) must be `Scope.REQUEST`; it is created in the child container that `app.fork()` makes
  per request. `Scope.SINGLETON` is shared by every request on the server.
- **`getRouter` is the lifecycle.** `createAppRouter` forks the container, creates the router, runs
  `ROUTER_PLUGIN_TOKEN`s and then the `server`/`client` command lines. Start calls it per request
  and once in the browser.
- **Pick the right render token.** `EXTEND_RENDER` wrappers sit in the router's `Wrap`, outside
  `<html>`, so they must not render DOM. Global providers that render markup or need the document
  (tooltips, toasts) go into `LAYOUT_OPTIONS_TOKEN` `wrappers`. `<html>`/`<body>` attributes go
  into `HTML_ATTRS_TOKEN`; `useAttrs` is a hook and runs on the server too.
- **Do not hand-write the document.** The root route uses `RootDocument` and `RootLayout` from
  `RenderModule`; extend them through tokens instead of editing `__root.tsx`.
- **HTTP goes through `HttpModule`.** Ask `HTTP_CLIENT_FACTORY_TOKEN` for a named client
  (`{ name, ...axiosOptions }`) rather than importing axios. Errors are `HttpError` with `status`
  (absent for network errors). Test with `mockAdapter`.
- **Streaming is decided in loaders:** `ensure*` waits for data (part of the first flush), and
  `prefetch*` without `await` streams it into a `<Suspense>` boundary that reads it with a suspense
  hook. Crawlers get the complete HTML (`isbot`), so test streaming with a browser user agent.
- **Query `fn` is a regular function.** `deps` and `signal` are bound to `this`.
- **Server-only code** goes through `createIsomorphicFn` (see `ui-store/themeCookie.ts`). Outside
  the Start compiler (Vitest) the server branch always runs, so inject such code through a token
  (`THEME_STORAGE_TOKEN`) and override it in tests.
- **Legacy decorators:** `experimentalDecorators: true`. Do not migrate `@Module` to TC39.
- **The theme** is `<html data-theme>` with `light-dark()` tokens in `styles.css`. Do not add
  hard-coded `bg-white` or `#fff`; use the tokens (`bg-card`, `bg-background`, …).
- **e2e** never hits the real API: new endpoints must be added to `e2e/mock-api.mjs`. Every test
  fails on console errors.
- `src/routeTree.gen.ts` is generated by the dev server or build. Run one of them after adding
  routes and before `typecheck`.
